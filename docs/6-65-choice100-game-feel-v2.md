# 6-65 선택100 GAME FEEL V2 + QUIZ DNA + 40 CHOICE

> 6-64 G1의 게임감을 올리는 작업. 고친 것:
> - 결과를 같은 화면에서 바로 보여 준다.

## 3. Quiz DNA interpretation

1999년 이후 국내 온라인 퀴즈 게임의 **루프 특성**만 가져왔다. 이름·그래픽·UI·캐릭터·문구·코드는 쓰지 않았다.

| 퀴즈 게임의 특성 | 선택100에서 |
|---|---|
| 진입이 빠름 | START(또는 Enter) 한 번 → 첫 상황, 규칙 설명 없음 |
| 행동이 짧음 | 한 번 탭(또는 키 1~4) |
| 즉시 결과 | 같은 화면에 결과·숫자 변화(0.45초 카운트) |
| 다음으로 자연스럽게 | [다음 선택 ▶] 한 번(또는 →), 버튼이 자동으로 화면 안에 |
| 점수 변화가 즉각적 | HUD 고정 + 초록/빨강 플래시 + 떠오르는 변화량 |
| 반복이 쉬움 | 엔딩에서 [한 판 더] 한 번, 지난 판과 비교 |

## 4. Game Feel V2 goals

P0 빠른 시작·반복 → P1 결과의 쾌감·긴장 → P2 초반 긴장 → P3 40선택 → P4 로컬 기록 → P5 엔진 재사용.
P3(시나리오 추가)는 P0~P2를 끝낸 뒤에 했다.

## 5. Core loop changes

```
[상황 카드] [선택 1~4]
      │ 탭/키 1~4
      ▼
[같은 화면] 고른 버튼 강조·나머지 흐리게 → 아래에 결과 카드(한 줄 + 변화 칩 + ⏳/⚠️ + 이번 달 흐름 + 💡TIP + [다음 선택 ▶])
      │ 탭/→                         (HUD는 위에 고정, 숫자 카운트·플래시·떠오르는 변화량)
      ▼
[다음 상황] 📰 사건 / 🔁 돌아온 과거 선택
```

- 클릭 수: 40선택에 84번. 선택 + 다음이 최소다. TIP을 읽을 틈을 남기려고 자동 넘김은 하지 않았다.
  키보드로는 1~4 → → 반복으로 마우스 없이 플레이한다.
- 첫 선택까지: START 후 바로 선택지(측정 0ms 렌더). 사람이 상황 한 줄을 읽는 시간만 걸린다.
- 모바일: 결과 뒤 [다음] 버튼을 화면 안으로 즉시 스크롤한다. HUD는 sticky라 함께 보인다
  (390px에서 6회 연속 측정: HUD 55~181px, 다음 버튼 770~836px / 화면 842px).
- 업데이트 후 옛 스크립트가 캐시에 남던 문제(실제 발견) → `index.html`에서 `engine.js?v=…` 형식으로 버전 쿼리.

## 6. Result animation

| 요소 | 구현 | 시간 |
|---|---|---|
| 숫자 카운트 | HUD 5칸, ease-out | 450ms |
| 색 플래시 | 좋아지면 초록, 나빠지면 빨강(부채·지출·위험은 반대) | 900ms |
| 떠오르는 변화량 | 칸 오른쪽 위 "+100만원" | 1s |
| 흔들림 | 선택 효과로 순자산 −300 이상 또는 경고 사건 | 320ms |
| 사건 아이콘 | 📰 사건, 🔁 돌아온 선택, ⏳ 나중에 돌아옴, ⚠️ 경고 | — |
| 진행 막대·카운터 | 선택 즉시 갱신 | 300ms |

`prefers-reduced-motion: reduce`이면 카운트·흔들림·떠오름·등장 애니메이션이 없고 값만 바뀐다.

## 7. Delayed consequences

- 엔진:
  - 선택이 `set_flags`를 켜면 "어느 선택에서 왔는지"(`flag_origin`: 선택 번호·시나리오·선택 글)를 기록한다.
  - 뒤 시나리오의 `triggers`가 발동하면 `enter_echoes`에 원래 선택과 함께 남긴다.
  - 화면: 🔁 "선택 02 「임시 치료만 30만원」의 결과" + 사건 글.
- 선택 직후에는 결과를 다 보여 주지 않는다. "⏳ 이 선택은 나중에 다시 돌아올 수 있습니다."만 표시한다(`out.delayed`).
- 비율: **159개 선택 중 32개(20.1%)**. 이 선택이 들어 있는 시나리오는 21/40이다. 좋은 결과와 나쁜 결과를 섞었다.

| 나중에 좋게 | 나중에 나쁘게 |
|---|---|
| 친구 창업 투자 300 → 600(q024) | 임시 치료·참기 → 치료비 250(q008) |
| 주말에 도와줌 → 월 20만원 외주(q016) | 보증 → 1,000만원 빚(q019) |
| 운동 등록 → 월 5만원 절약(q012) | 임시방편 누수 → 300(q038) |
| 급락 때 추가 매수 → 회복 보상 | 변동금리 → 이자 +2%(q036) |
| 청약 준비 → 당첨(q039) | 보증금 안 챙김 → 반환 지연(q040) |
| 공부해 둠 → 광고 함정 회피(q040) | 바닥 매도 → 회복 때 속쓰림 |

- 검증 강화: 켜기만 하고 돌아오지 않는 flag는 이제 **데이터 오류**다. 6-64에 이런 flag가 4개 있었다(family_loan·studied·want_house·hot_tip_small). 모두 챕터 4에서 돌아오게 했다.

## 8. Early-game tension (1~10)

| # | 제목 | 역할 |
|---|---|---|
| 1 | 뜻밖의 보너스 | 즉시 결과·trade-off(상환/현금/투자/소비) |
| 2 | **갑자기 이가 아프다** | **작은 위기** + 미루기 선택 → 선택 8에서 돌아옴 |
| 3 | **친구의 창업 제안** | **작은 기회** + 투자/응원/시간 → 선택 16·24에서 돌아옴 |
| 4 | 고정비 다이어트 | 정답 없는 절약(해지=즐거움↓, 운동=비용↑ 대신 선택 12에서 돌아옴) |
| 5 | **부모님 환갑** | 가족 vs 돈, 특근(현금↑·행복↓) |
| 6~10 | 성과급·비상금·자동차(+치통 귀환)·환급·스카우트 | 기존 유지 |

6-64의 "가계부"·"점심값"은 뺐다(대가가 약해 답이 보이던 선택). 초반 10개 안에 즉시 결과·trade-off·미래 trigger·작은 위기·작은 기회가 모두 들어 있다.
TIP은 판정하지 않도록 새로 썼다. 예: "미룬 비용은 사라지지 않고 뒤로 옮겨질 때가 많습니다", "거절도 선택입니다. 기회비용이 있을 뿐입니다".

## 9. Player style

- 규칙은 데이터(`style.rules`)에 있다. **선택의 실제 변화량**(월 흐름 제외)으로 센다.

| 조건 | 스타일 |
|---|---|
| 부채 ↓ | debt_focus 💳 부채 정리형 |
| 투자 ↑ | investment_focus 🚀 기회 추구형 |
| 행복 +4 이상 & 현금 ↓ | consumption_focus 🎉 지금을 즐기는 형 |
| 위험 +8 이상 | risk_taker 🎲 승부사형 |
| 위험 −4 이하 | risk_averse 🛡️ 안정 추구형 |

- 가장 많은 스타일이 34% 미만이면 🎯 균형 전략형이다.
- 엔딩 화면에 표시하는 문구: "게임 내 선택을 기준으로 한 플레이 스타일입니다. 실제 금융 성향 진단이 아닙니다."
- Chrome 실측:
  - 부채 중심 → 🛡️ 안정 추구형
  - 투자 중심 → 🚀 기회 추구형
  - 소비 중심(키워드 선택 + 기본 선택 섞임) → 🎯 균형 전략형

## 12. Local analytics

`analytics.js` — `create(storage, gameId, version, clock)`. 저장소를 주입하므로 테스트는 메모리 저장소를 쓴다.

| 이벤트 | 기록 |
|---|---|
| `game_start` | 시각, 버전 |
| `choice_made` | 선택 번호, 시나리오 id, 선택 id |
| `game_completion` | 엔딩 |
| `game_restart` | 진행 중 새로 시작 또는 [한 판 더] |

- 판(run) 기록: game_id, version, started_at, completed_at, choice_count, play_time_sec, restart_count, ending, style, net_worth, debt, happiness.
  **개인정보 필드 없음**(테스트로 키 목록 고정).
- play_time: 이벤트 사이 간격의 합이다. 간격마다 최대 120초까지만 센다(창을 켜 둔 채 자리를 비운 시간 제외).
- 보관: 이벤트 최근 300개, 판 최근 30개.
- 손상되면 새로 시작한다. 저장이 막힌 환경에서도 게임은 계속된다(테스트).
- **서버 전송·외부 API 없음**: `analytics.js`에 fetch/XHR/sendBeacon/WebSocket/URL이 없음을 테스트로 확인한다.
- Chrome 실측(자동 플레이 3판): 시작 3 · 끝냄 3 · 다시 하기 2. 플레이 시간은 자동이라 0초 — 실제 사람 플레이에서 채워진다.

## 13. Mobile accessibility (390px, 실제 Chrome)

| 화면 | 가로 넘침(scrollWidth − clientWidth) |
|---|---|
| 타이틀 / 플레이 / 결과 / 중간 결과 / 엔딩 / 플레이 기록 | 0 / 0 / 0 / 0 / 0 / 0 |
| 긴 글 주입(띄어쓰기 없는 600자 상황 / 200자 선택지 / 400자 결과·TIP) | 0 / 0 |

- 선택 버튼 높이 57px, 간격 8px.
- 글자 크기: 상황 16.8 / 선택 16.8 / 결과 18.4 / TIP 16 / 주 버튼 20px.
- 접근성:
  - `:focus-visible` 3px 윤곽선, 주 버튼에 자동 포커스(터치 기기에서는 선택지에 포커스 안 줌)
  - 선택지 그룹 `aria-label="선택지 (키보드 1~4)"`, `aria-keyshortcuts`
  - 고른 버튼 `aria-pressed`
  - 결과 `role="status"`
  - HUD `role="group" aria-label="재무 상태"`
  - 진행 `role="progressbar"`
  - "이 게임에 대해" `aria-expanded`
- 키보드: 1~4 선택, → 다음, 아무것도 포커스 안 됐을 때 Enter = 주 버튼(실제 키 입력으로 START → 선택 → 다음 확인).
- `prefers-reduced-motion`: CSS와 JS 둘 다 처리. 코드와 테스트로 확인했다. Chrome에서 해당 설정을 켜고 본 것은 아니다.

- 소비만 해도 행복형이 아니다(17%). 투자만 해도 공격형이 아니다(29%, 순자산 1억을 넘겨야 공격형). 부채 상환만 해도 안정형이 아니다(61%).
- 어느 전략도 한 엔딩이 90%를 넘지 않는다(테스트).
- 40선택으로 늘리며 바꾼 규칙:
  - 행복도·위험도를 **평균으로 돌아가는 값**으로 바꿨다(매달 행복 60, 위험 30 쪽으로 조금씩). 30턴 넘게 쌓기만 하면 누구나 행복 100·위험 100이 되던 문제를 막았다.
  - 위기 = 순자산 6,000만원 미만(월급만 모았어도 닿았을 금액).
  - 행복형 = 행복 ≥ 85 이고 위험 < 70.
  - 공격형은 한방형보다 먼저 보고, 순자산 ≥ 1억 이어야 한다.
  - 한방형 = 위험 ≥ 75.
- 조정 과정(실측): 첫 40선택 시뮬레이션에서 행복형 60% → 행복 감쇠만 넣자 한방형 37% → 평균 회귀 + 엔딩 순서·조건 조정 → 위 분포.

## 18. Risks

| 위험 | 대응 |
|---|---|
| 결정적 결과라 2회차부터 "정답"을 외움 | 지금은 선택 조합이 많고 돌아오는 결과가 좋고 나쁨이 섞였다. 필요하면 G3에서 시드 기반 작은 변동 검토(운빨 금지 원칙 유지) |
| 트리거 남발로 억지스러움 | 선택의 20%로 제한(테스트: 15~30%) |
| 스타일을 실제 성향 진단으로 오해 | 엔딩에 "실제 금융 성향 진단이 아닙니다" 고정 |
| 로컬 기록이 개인정보로 번짐 | 필드 목록 테스트로 고정, 전송 코드 없음 테스트 |
| 캐시된 옛 스크립트 | `?v=` 버전 쿼리 |
| 부동산 내용이 조언처럼 읽힘 | 법·세금·규정·지역·은행명 없음, 면책 문구 |
