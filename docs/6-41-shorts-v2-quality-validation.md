## 1. 6-40 문제점

6-40은 기술적으로 성공했다(1080x1920/H.264 MP4 3개). 하지만 구조 자체가 카드뉴스였다:

- 아이보리 배경 + 얇은 테두리 + 둥근 흰 카드 + 58px 고딕 본문 4~6줄 — 모든 화면이 같은 틀
- 정적 PNG를 concat 하드컷으로 이어붙임 → 화면 안에서 움직이는 것이 전혀 없음
- 무음(`-an`)
- 첫 화면이 "대출 받을 때 은행이 먼저 보는 3가지" 같은 **제목 표지**
- 카드 문장이 "~해요/~더라고요"로 길게 이어지는 설명문 → 화면에 글을 붙인 느낌
- 중요 텍스트 위치를 플랫폼 UI 기준으로 검사하지 않음

## 4. 디자인 원칙

1. **움직여야 할 이유가 있는 요소만 움직인다.** 배경은 느리게(장면당 줌 4~7%), 텍스트는
   등장/퇴장 순간에만, 강조는 한 번만. 흔들림/회전/번쩍임/색 순환은 쓰지 않았다.
2. **한 화면 최대 3줄.** 넘치면 렌더러가 **폰트를 줄이지 않고 실패**한다
   (`layout_text` → `ShortsRenderError: 폰트를 줄이지 말고 문장을 줄이세요`). 실제로
   이 규칙에 걸려 AI 영상 TAKEAWAY 문장을 두 번 고쳤다(13장).
3. **강조는 한 단어/구 하나.** 대본에서 `*단어*`로 표시 → 스타일별로 금색+밑줄(금융),
   따뜻한 호박색(인간관계), 라임 형광펜 박스(AI). 연속된 강조 어절은 하나의 박스로 합친다.
4. **Safe area 강제.** 모든 텍스트/칩/숫자/목록 bbox를 렌더러 생성 시점에 검사 — 벗어나면 실패(8장).
5. **HOOK은 첫 프레임부터 보인다.** 등장 애니메이션을 앞당겨(headstart) t=0에 이미 글자가 있다.
6. **장면 전환은 박자 위에서.** 장면 길이 = 박자의 정수배.

## 5. 콘텐츠 원칙 ("AI 느낌" 줄이기)

문장을 짧게 자르는 것만으로 해결하지 않고 **콘텐츠 구조**를 바꿨다.

- 나쁜 구조(6-40 류): "정리하면 은행은 상환능력·부채·신용을 종합적으로 봐요."
- 6-41 구조: **구체 상황**("신용점수 괜찮은데 대출이 안 나왔다면?") → **관찰**(점수 하나로
  결정하지 않는다) → **구체 요소 3개**(각각 그래픽) → **반전/정리**(연봉이 같아도 결과가
  다르다, 은행 용어로는 DSR) → **바로 할 수 있는 행동 하나**(신청 전에 소득 대비 빚부터 계산).
- 추상 결론("결국 중요한 건 사람입니다", "우리에게 필요한 것은…")을 쓰지 않았다.
- 끝맺음은 교훈이 아니라 **오늘 할 수 있는 행동**: "'잘 지내?' 한 줄", "질문을 한 줄로 먼저 적어 보자".
- clickbait 금지어("충격/무조건/100%/은행이 숨기는 비밀") 미사용.
- 금융: 규정 수치를 만들지 않았다. DSR은 실제 용어(연 소득 대비 연간 원리금 상환액 비율)이며
  화면에 "※ 적용 기준은 대출 종류·시기마다 다릅니다"를 함께 표시했다.
- AI: 예언/과장 없음. "30분 → 30초", "보고서 10개를 금방 요약" 은 개인 관찰 톤의 예시다.

## 7. 구현 구조

6-40 렌더러를 폐기하지 않고 위에 레이어를 얹었다.

### Voice / Narration (VERSION A/B)

- 이번 결과물은 **VERSION A(음악 + 효과음 + kinetic text)**.
- VERSION B를 위한 구조만 넣었다: `Scene.voiceover` 필드(금융 HOOK에 예시 1개). TTS/음성 합성
  시스템은 만들지 않았다 — 저장소에 기존 음성 인프라가 없다. 추후 VO wav를 받아 음악 덕킹
  후 믹스하는 단계만 추가하면 된다(`synthesize_soundtrack`의 music 버스에 이미 사이드체인
  덕킹 구조가 있음).

## 12. 발견 문제 (렌더링 사이클별)

**미리보기(인코딩 전 contact sheet) 단계**
1. 반투명 요소가 불투명하게 나옴 — RGBA 프레임에 ImageDraw로 반투명 도형을 그리면 블렌딩이
   아니라 알파값 덮어쓰기가 되고, 최종 RGB 변환에서 격자선이 흰 선, A/B 카드가 회색 판으로 보였다.
2. AI 강조 박스가 어절마다 따로 끊겨 보임("사람은 | 뭘 | 해야").
3. "30초" 장면 문장이 2줄로 감기면서 취소선 "30분"과 겹침.
4. "이 기준을 한 단어로 하면" → "하면" 한 단어가 혼자 줄바꿈 / "뭘 찾을지 정하는 힘" → "힘" 고아 줄.
5. 3줄 초과로 렌더 실패: "AI한테 묻기 전에 / 내 질문부터 한 줄로 / 적어 보자."(4줄) — 규칙이 의도대로 동작.
6. 인간관계 명조체가 가늘고 작음(74px 600).

**1차 렌더링(MP4)**
7. **세 영상 모두 첫 프레임에 Hook 문장이 없음** — 등장 애니메이션 대기 시간 때문. 스크롤을
   멈추게 해야 할 첫 0.1초가 빈 배경이었다(가장 중요한 결함).
8. 파일 크기 과대(human 111.7MB) — 매 프레임 바뀌는 그레인 + CRF 18.
9. 금융 하이햇/클랩이 과하게 밝음(스펙트로그램 전 대역 에너지).
10. AI 스캔 라인이 두꺼운 띠로 보여 렌더링 오류처럼 보임.
11. 금융 Hook 알림 카드와 상단 워터마크 겹침.

**2차 렌더링(MP4)**
12. human 디졸브 중 이전/다음 장면 문장이 같은 위치에 겹쳐 보임.
13. AI 진행 바가 상단 UI 가림 영역에 위치.

## 14. 남은 문제

- **실제 청취/재생 확인을 하지 못했다.** 오디오 품질(음색이 "싸구려 신스"처럼 들리는지),
  효과음 볼륨 밸런스는 지표로만 확인했다. 합성 음원은 테스트용이며 실제 업로드에는
  YouTube 오디오 라이브러리 등 라이선스가 명확한 음원이 더 적합할 가능성이 높다.
- 배경은 절차적 그래픽이다. 실제 사진/영상 소스(직접 촬영·라이선스 확보 스톡)가 있으면
  인간관계 스타일은 훨씬 더 "영화 같아질" 수 있다 — 이번에는 저작권 원칙상 사용하지 않았다.
- 폰트가 Windows에 설치된 Noto Sans/Serif KR 가변폰트에 의존한다(다른 PC/CI에서는 렌더 테스트 skip).
- human 파일이 47MB로 큰 편(업로드엔 문제 없지만 저장 공간 측면).
- AI HOOK 첫 프레임에서 "30분" 숫자는 아직 페이드 인 중(약 30% 불투명) — 문장은 완전히 보임.
- 인간관계 장면 사이 약 0.5초의 "글자 없는 호흡" 구간이 있다(의도). 너무 느리게 느껴질 수 있음.
- `spec_from_shorts_script()`로 6-40 카드뉴스 대본을 그대로 옮기면 대부분 3줄/길이 규칙에 걸린다
  — 의도된 게이트지만, 기존 콘텐츠 파이프라인(ShortDraft → ShortsScript)은 아직 v2 장면 설계를
  생성하지 못한다.

## 15. 다음 개선 방향

1. 사용자가 3개 영상을 직접 보고 스타일 하나(또는 조합)를 선택 → 그 스타일만 템플릿화.
2. 콘텐츠 생성 단계가 v2 장면 설계 JSON(Hook/Beat sheet/emphasis/visual)을 직접 출력하도록 연결.
3. 라이선스가 명확한 음원(YouTube 오디오 라이브러리 등)으로 교체 실험, VERSION B(내레이션) 비교.
4. 인간관계 스타일에 직접 촬영한 실사 배경 적용 실험.
5. 폰트 파일을 라이선스 확인(OFL) 후 저장소에 포함하거나 경로 설정화 → 다른 PC 재현성.
6. 실제 스마트폰에서 YouTube 앱 UI 위에 올려 safe area 수치 재검증.
