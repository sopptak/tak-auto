## 2. 실행 명령

먼저 `scripts/run_media_batch.py`의 `--help`/코드를 확인해 이 KNOWLEDGE 1건만
대상으로 실행하는 옵션(`--id`)이 이미 존재함을 확인했다(코드 수정 없이 그대로
사용). Dry-run으로 대상 필터링이 정확한지 먼저 검증한 뒤 실제 LLM 실행을
진행했다.

Dry-run 확인:
```
$ python3 scripts/run_media_batch.py --id knowledge-scout-b28b782b2a33
전체 KNOWLEDGE: 1건 / 승인 KNOWLEDGE: 1건 / 예상 생성 Draft: 9건
```

실제 LLM 실행(환경변수는 이번 명령에만 적용, API 키는 세션에 이미 설정되어
있던 값을 그대로 사용했고 값 자체는 출력하지 않음):

```
TAK_MEDIA_LLM_ENDPOINT="https://api.openai.com/v1/chat/completions" \
TAK_MEDIA_LLM_MODEL="gpt-4o-mini" \
python3 scripts/run_media_batch.py \
  --id knowledge-scout-b28b782b2a33 \
  --execute \
  --output data/tak_media_batch_dario_first_test.json
```

결과는 별도 테스트 파일 `data/tak_media_batch_dario_first_test.json`에
저장했다(기존 배치 결과 파일들과 분리, `.gitignore`의 `data/*.json` 규칙에
포함되어 git 추적 대상 아님).

- **단순 "AI 찬성" 의견으로 축약되지 않았다.** 어떤 draft도 "AI를
  지지한다/찬성한다" 같은 단순화된 문장으로 바꾸지 않았고, 모두 "두려움을
  넘어 직접 경험해봐야 한다"는 원래의 태도(용기/직접경험 프레이밍)를
  유지했다.

  귀중하다"는 **새로운 일반화된 주장**을 추가했는데, 이는 "의미 왜곡"은
  아니지만 "원본에 없는 확장된 주장 추가"에 해당하며 Validator가 정확히 이
  부분을 잡아냈다.

## 10. 품질 평가

- **Validator는 의도대로 작동했다.** 근거 없는 일반화(Blog의 "경험이 설명보다
  귀중하다")와 금융 면책 문구 누락을 정확히 잡아냈다. 이는 5-3 실전 테스트에서
  관찰된 패턴과 일치한다.
- **다양성 부족이 뚜렷하다.** Shorts 3건, Threads 5건 모두 "AI 위험 우려 언급
  + 두려워 말고 부딪히자"는 동일한 틀을 반복 재생산했다. KNOWLEDGE에 담긴
  근거(사실 1개 + 의견 1문장)가 짧다 보니 LLM이 변주할 재료가 부족했던 것으로
  보인다.
- **"경험" 단어 하나로 인한 과다 거부 가능성.** 7/9건이 이 단어 때문에
  거부됐는데, 사용자의 원래 문장 자체가 "느껴봐야 한다"(경험을 의미)이므로,
  이 판정 기준이 다소 과도하게 엄격할 수 있다는 인상을 준다. 다만 이번
  단계에서는 코드/검증 로직을 수정하지 않았으므로 이는 **관찰된 현상**으로만
  기록한다.
- **최종 사용 가능 콘텐츠는 Threads 1건뿐**이라, 애초 목표였던 "Blog 1 +
  Shorts 3 + Threads 5" 전체 활용은 이번 실행 결과로는 달성되지 않았다.

## 11. 문제점

1. Blog·Shorts는 전멸(0/1, 0/3)했고 Threads도 5건 중 1건만 통과해, 목표
   수량(1/3/5) 대비 실사용 가능한 콘텐츠가 크게 부족하다.
2. Shorts·Threads 내부적으로 서로 다른 draft 간 표현이 거의 동일한 틀을
   반복해 다양성이 낮다.
3. Blog draft에서 "경험이 어떤 설명보다도 귀중하다"는 원본에 없는 일반화
   주장이 추가됨(다행히 Validator가 거부해 최종적으로 사용되지는 않았다).
4. Blog draft에서 금융 면책 문구가 재작성 중 누락됨(역시 Validator가 거부).
5. "경험"이라는 단어 하나로 대부분의 draft가 거부되는 패턴이 반복되어,
   근거(evidence) 1~2줄짜리 짧은 KNOWLEDGE에는 현재 Validator 기준이 다소
   가혹하게 작동할 가능성이 있다.
6. 모든 draft에서 `content_id`가 `None`으로 기록되어 있다 — valid 항목에
   대한 후속 id 채번 단계가 있는지 여부는 이번 조사 범위에서는 확인만 하고
   코드는 들여다보지 않았다.

## 12. 다음 개선사항 (제안, 이번 단계에서는 실행하지 않음)

1. KNOWLEDGE의 evidence를 좀 더 풍부하게(배경 설명, 추가 근거 문장 등) 채워
   LLM이 다양하게 재작성할 재료를 늘리는 방안을 검토한다.
2. Validator의 "사실 범위 확장" 판정 기준(특히 "경험"류 단어 처리)이 짧은
   의견형 KNOWLEDGE에도 적합한지 별도로 검토한다(코드 변경은 사용자 승인 후
   별도 단계에서).
3. Blog 재작성 프롬프트에 "원본에 없는 새로운 일반화 주장을 추가하지 말 것"과
   "금융 면책 문구를 반드시 그대로 유지할 것"을 더 명확히 지시하는 방안을
   검토한다.
4. 이번에 유일하게 valid로 통과한 Threads 항목 1건을 실제 게시할지 여부는
   사람이 별도로 검토·결정한다(이번 단계에서는 게시하지 않았음).
5. 코드 수정, Threads/Naver 게시, commit/push는 모두 사용자의 별도 지시가
   있을 때 진행한다.
