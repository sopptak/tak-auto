> TAK GAME FACTORY 첫 실험(G1, `docs/6-63-game-factory-candidate-strategy.md` 19장). **플레이 가능한 웹 프로토타입**이다.

## 1. Executive Summary

- 공통 엔진 `engine.js`를 만들었다. DOM이 없고 도메인을 모르며, 데이터 JSON이 게임을 정한다. 화면은 `renderer.js`, 금융 데이터는 `data/finance.json`.
- **금융 시나리오 30개**(챕터 1~3)를 실제로 플레이할 수 있다. 100선택 구조는 10챕터 × 10으로 데이터에 정의돼 있다. 31~100은 같은 schema로 추가하면 된다.
- 루프: 상황 → 선택 → 즉시 결과(숫자 카운트 애니메이션 + 변화 칩) → 한 줄 TIP → 다음. 10개마다 중간 결과, 30개째에 G1 엔딩(7종).
- 실제 Chrome에서 30선택을 끝까지 플레이했다. 콘솔 오류 없음, 390px 가로 넘침 0.
- 테스트: node 엔진 11개 + Python 9개(데이터 독립 검증·JS 스위트·시뮬레이션·화면/가드레일/분리).
  자동 플레이어로 305판 시뮬레이션: 7개 엔딩 모두 도달, 전략마다 결과가 다름.

## 2. Game Vision

"내가 100번의 선택으로 얼마나 부자가 될 수 있을까?"
- 공부하려고 하는 게임이 아니다. 재미있어서 계속 누르다 보니 금융 상식이 쌓이는 게임이다.
- 금융교육 사이트·문제집·계산기처럼 보이지 않게: 어두운 게임 화면, 큰 버튼, 카운트 애니메이션, 챕터 "끝!" 연출, 엔딩 아이콘.

## 3. Game Director Priority

1순위 빠르고 극적인 게임성 → 2순위 현실적인 재무 시뮬레이션 → 3순위 학습.
구현에 반영한 것:
- 첫 화면 START 한 번이면 바로 첫 상황이다(측정: 클릭 후 첫 선택지 표시까지 3ms, 설명 화면 없음).
- 한 화면에 숫자는 HUD 5개뿐이다(현금·부채·투자·순자산·행복도).
- 결과는 칩 몇 개 + TIP 한 줄이다.
- 긴 설명, 표, DSR/LTV/세법 같은 용어는 없다.

## 4. Core Game Loop

```
[상황 카드 + 사건 📰] → [선택 1~4] → [결과: 한 줄 + 변화 칩 + '이번 달 흐름' + ⚠️사건] → [💡 TIP] → [다음 선택 ▶]
     ↑                                                                                              │
     └───────────── 10개마다 [CHAPTER n 끝! 순자산 +X만원] → [계속하기] ──────────────────────────────┘
                                   30개째 → [게임 결과: ○○형] → [다시 하기]
```

- 선택 한 번 = 한 달. 매달 규칙(`per_turn`): 현금 += 월소득 − 월지출, 부채 += 부채 × 0.4%(이자), 투자 += 투자 × 0.4%(게임 가정).
- 칩은 **선택 효과만** 보여 준다. 매달 흐름(월급·이자)은 "이번 달 흐름" 한 줄로 따로 보여 줘서 선택의 결과가 흐려지지 않게 했다.
- 키보드 1~4로도 고를 수 있다(PC).

## 7. Financial state model

| 변수 | 시작 | 화면 | 범위 |
|---|---|---|---|
| cash 현금 | 3,000만원 | 💰 | 0 미만이면 마이너스 대출로 전환(신용 −5, 위험 +5) |
| debt 부채 | 2,000만원 | 💳 | ≥ 0 |
| investment 투자 | 0 | 📈 | ≥ 0 |
| asset 자산 | 3,000만원 | (순자산에 포함) | ≥ 0 |
| income 월소득 | 400만원 | 결과 칩 | ≥ 0 |
| expense 월지출 | 250만원 | 결과 칩 | ≥ 0 |
| credit 신용 | 70 | 결과 칩 | 0~100 |
| risk 위험도 | 30 | 결과 칩 | 0~100 |
| happiness 행복도 | 70 | 😊 막대 | 0~100 |
| **net_worth 순자산** | 4,000만원 | 🏦 | = 현금 + 투자 + 자산 − 부채 (`derived`) |

단위는 게임 내부 1 = 1만원이고, 1억 이상은 "1억 2,500만원"처럼 표시한다. 모든 수치는 가상의 게임 수치다(화면에 명시).

## 8. Game mechanics

- **효과**:
  - 숫자(더하기)
  - `{pct}`: 현재 값의 %, 예: 급락 −25%
  - `{set}`: 값 지정
- **moves**: 한 변수의 일부를 다른 변수로 옮긴다. 예: 투자 30% → 현금, 투자 30%로 부채 상환(`reduce`).
- **requires**: 조건이 안 되면 버튼을 비활성화하고 이유를 보여 준다("현금 500만원 이상 필요"). 시나리오마다 조건 없는 선택이 최소 1개다(검증).
- **flags + triggers**: 지금 선택이 나중에 돌아온다. 이게 가장 게임다운 장치다.
  - 친구에게 500 빌려줌 → 5턴 뒤 300만 갚음
  - 보증 → 6턴 뒤 1,000만원 빚
  - 몰빵·코인·급등주 → 급락 때 추가 손실
  - 급락 때 추가 매수 → 회복 때 보상
  - 바닥에서 매도 → 회복 때 행복도 −8
  - 부업 → 월소득 +10
- **add_per_turn**: 자동 투자·노후 적립처럼 한 번 정하면 매달 반복되는 선택.
- **guards**: 현금 부족 시 자동 마이너스 대출 + 경고 사건.
- **trade-off 원칙**: 모든 선택에 대가가 있다. 예:
  - 상환: 부채↓ 위험↓ 현금↓
  - 투자: 투자↑ 위험↑ 현금↓
  - 소비: 행복↑ 현금↓
  - 저축: 위험↓ 성장 없음

  데이터 테스트가 "한 시나리오 안 선택지 효과가 모두 같지 않음"을 확인한다.

## 13. UI architecture

- `engine.js`(규칙) / `renderer.js`(화면) / `data/*.json`(내용) / `index.html`(CSS). 외부 스크립트·폰트·CDN이 없다.
- 화면: 타이틀 → 플레이(상단 "선택 NN / 100" + 챕터 + 진행 막대, HUD 5칸, 상황 카드, 선택 4개) → 결과 → 중간 결과 → 엔딩.
- 모바일 우선:
  - 최대 폭 480px, 좌우 16px
  - 본문 16px 이상(상황 18.4px, TIP 16px, 버튼 16.8~20px)
  - 선택 버튼 높이 57px 이상
  - `overflow-wrap:anywhere`
  - safe-area
- 연출:
  - 숫자 카운트 500ms
  - 오르면 초록, 내리면 빨강 배경 플래시(부채·지출·위험은 반대 색)
  - 카드 등장
  - `prefers-reduced-motion`이면 애니메이션 없음
- 저장: `localStorage`(try/catch, 데이터 id·version이 다르거나 손상되면 버림) → "이어하기 · N개 선택함".

## 14. Web → PWA → App migration plan

1. **Web(G1)**: 정적 파일 4개 + JSON.
2. **PWA**: `manifest.json` + service worker(정적 파일 캐시)만 추가한다. 엔진·데이터는 그대로다. 오프라인 플레이가 가능해진다.
3. **App**: WebView 래퍼(Capacitor 등)에 같은 정적 파일을 넣는다. 저장은 `store()` 한 곳만 바꾼다.
4. 여러 게임: `boot(root, "data/hanja.json")`처럼 데이터 경로만 바꾼다(엔진 테스트에 한자 미니 게임으로 확인).

## 18. Risks / guardrails

- 타이틀과 모든 화면의 "이 게임에 대해"에 전문 표시: "본 게임은 금융 의사결정 학습을 위한 가상 시뮬레이션이며 실제 금융상품·투자·대출에 대한 조언이 아닙니다." 엔딩에는 "게임 결과이며 실제 재무 평가나 조언이 아닙니다."
- 특정 상품·종목·기관 추천 없음(테스트). 실제 금리·수익률 단정 없음. 이자 0.4%·투자 0.4%/월, 급락 −25%·회복 +35%는 **게임 가정**이다.
- 대출 승인 판단·수익 예측 도구가 아니다. 금융기관 내부정보를 쓰지 않았다.
- 시뮬레이션 결과는 stdout에만 나간다. 어디에도 성과로 저장하지 않는다(6-63 16장).
- 운빨 방지: 무작위 없음.
- 범위 폭주 방지: 30개, 정적 파일, 새 dependency 0.
